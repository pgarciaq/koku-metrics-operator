# AGENTS.md - koku-metrics-operator

## Project Context

Kubernetes operator (Go, Operator SDK) that collects OpenShift cluster metrics and uploads them to Red Hat's cost management service. Installed and managed via OLM. CRD: `CostManagementMetricsConfig` (alias: `MetricsConfig`).

## Critical: Upstream vs Downstream

Always develop on **main** (upstream) first. Downstream receives ported changes.

| | Upstream (main) | Downstream |
|---|---|---|
| Name | koku-metrics-operator | costmanagement-metrics-operator |
| CI | GitHub Actions (`.github/workflows/`) | Konflux/Tekton (`.tekton/`) |
| Dockerfile | `docker.io` base images | `brew.registry.redhat.io` base images |

Do NOT modify `.tekton/` on upstream or `.github/workflows/` on downstream. Makefile/Dockerfile differences between branches are intentional (e.g., `CGO_ENABLED=0` upstream vs `CGO_ENABLED=1` downstream for FIPS).

## Tech Stack

- Go (see `go.mod` for version) / Operator SDK / controller-runtime
- Ginkgo v2 + Gomega for testing
- OpenShift 4.5+ / Prometheus / OLM

## Key Architectural Facts

- Reconciler requeues every 5 minutes; packaging/upload gated by `upload_cycle` (default 6 hours)
- Basic auth is **deprecated** -- use token or service-account auth only
- `internal/storage/storage.go` reads the owning ClusterServiceVersion to patch Deployment volume mounts
- OLM bundle generated by `make bundle`; `bundle/` **is** committed and is
  regenerated on release branches, so it can lag `config/` between releases
  (`hack/verify-bundle-drift.sh` reports the gap, and a branch image installed
  under a stale bundle gets `forbidden` plus an empty CR status)
- Query lookback window defaults to 14 days (Prometheus query range, not report retention)
- Report retention controlled by `max_reports_to_store` (default 30)
- CRD changes can break existing clusters -- never remove fields, change types, or make optional fields required

## RBAC and generated files

- `config/rbac/role.yaml` is generated. RBAC changes go through a
  `+kubebuilder:rbac` marker on the controller; a hand edit survives until the
  next `make manifests` erases it, and the bundle is regenerated from the erased
  file — so nothing downstream complains.
- `make verify-manifests` (runs `make manifests`, diffs `config/`) is the check
  that fails a hand edit. `hack/verify-bundle-drift.sh` only warns, and is
  advisory off release refs.
- `internal/collector/rbac_grants_test.go` covers what the marker chain cannot:
  a dynamic client names its GVR in code, so controller-gen never sees it. The
  test reads the generated `role.yaml` and fails when a collector read has no
  ClusterRole grant, and a tripwire fails a collector file that builds a GVR with
  no row in the table. Add the row and its `+kubebuilder:rbac` marker together.
- A push runs CI only for `downstream`, `main`, and `pgarciaq-rosocp-superpowers-*`;
  any other branch is checked when a PR exists. Confirm with
  `gh run list --repo pgarciaq/koku-metrics-operator --event push`.

## Branch bundle deploys

- `hack/retarget-bundle.sh <image-ref>` writes the CSV's three image sites and
  re-reads them. OLM deploys the deployment container's image; the
  `containerImage` annotation and `relatedImages` only look right, so retargeting
  two of three installs upstream's image under a CSV that reports `Succeeded`.
- `hack/build-index-image.sh <configs-dir> <image-ref>` generates the Dockerfile
  with **both** stages pinned (`opm generate dockerfile` defaults both to
  `:latest`; `-i` pins only the final stage), validates the catalog, builds, and
  requires the `serving registry` log line. An index image with no `CMD` runs
  `opm` with no arguments, exits 0, and leaves the catalog pod in
  `CrashLoopBackOff` with empty logs.
- Neither script pushes or edits `bundle/` by default, and `make hack-selftests`
  pins both guards without a cluster or a container runtime.
- Reinstalling at the **same CSV version** needs the CatalogSource deleted and
  re-applied, not just repointed: `spec.image` changes while
  `status.connectionState.lastObservedState` still reads `READY` from the
  previous catalog pod, so a "wait for READY" step passes against a catalog
  that has not connected yet and OLM resolves the InstallPlan from the old
  content. Gate on `status.registryService.createdAt` plus a `lastConnect`
  later than the new pod's creation before recreating the Subscription
  (observed 2026-10-31: the InstallPlan was created 5 s before the new catalog
  pod's first successful connect and installed the previous digest under a
  `Succeeded` CSV, #745).

## Contributor Workflow (Pre-PR)

- Minimum local check before commit: `make fmt && make test`
- `make lint` is not CI's lint. The pre-commit hook runs
  `golangci-lint run --new-from-rev HEAD --fix`, so it only reports issues on
  lines changed since `HEAD`, while `validate-pr` runs plain `golangci-lint run`.
  Removing the last *use* of a variable leaves the `unused` finding on an
  unchanged declaration line and passes locally, so run what CI runs before
  pushing that kind of change: `golangci-lint run ./...`. `.golangci.yaml` sets
  `issues.fix: true`, so that run may autofix unrelated files — revert anything
  outside your change.
- Recommended pre-PR checklist:
  - `make fmt`
  - `make lint`
  - `make test`
  - `make verify-manifests`
  - `git status`
  - verify no secrets/tokens/credentials in staged files
  - for CRD changes, verify backward compatibility (no removed fields, no type changes, no optional-to-required changes)

## Code Conventions

- Standard Go formatting (gofmt), structured logging (zap)
- Wrap errors with context: `fmt.Errorf("context: %w", err)`
- Controllers must be idempotent
- Tests: follow the existing style in the touched package (Ginkgo in controller/integration areas, stdlib `testing` where already established); mock external dependencies (HTTP, filesystem, K8s API)
- Import order: stdlib, external (alphabetical), internal (alphabetical), blank lines between groups
- Never modify `vendor/` manually (use `make vendor`)
- Run at least `make fmt && make test` before committing; run full pre-PR checklist before opening/reviewing a PR

## Project Structure

```
cmd/main.go             # Entry point
config/                 # Kubernetes manifests, kustomize, OLM CSV base
internal/
  controller/           # Reconciliation logic
  collector/            # Prometheus metrics collection
  crhchttp/             # HTTP client for console.redhat.com
  sources/              # Sources API integration
  storage/              # Report storage, OLM CSV volume patching
  packaging/            # Report packaging (tar.gz)
  dirconfig/            # Directory configuration
  clusterversion/       # OpenShift ClusterVersion detection
  testutils/            # Testing utilities
```

## Security Boundaries

- Never commit secrets or log sensitive data (tokens, passwords)
- Validate CRD input before processing
- Validate file paths to prevent directory traversal
- Respect RBAC -- do not escalate permissions
